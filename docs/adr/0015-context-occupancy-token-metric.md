# Context-Occupancy Token Metric for Budget Thresholds

We decided that the 120k/135k/150k budget compares against current context-window occupancy — the latest `step_finish` part's token payload (`total` when present, otherwise input + output + reasoning + cache read + cache write) — rather than a cumulative sum over steps, because the `--format json` stream exposes only per-step counts and the budget exists to pre-empt context exhaustion, not to track spend; a resumed handoff run therefore reports the true (larger) occupancy and keeps the ceiling check honest. The ceiling is `min(configured_ceiling, model_context_limit)`, with the model limit an optional argument until multi-model routing exists. This supersedes the spec's wording about extracting "cumulative input and output token counts".
