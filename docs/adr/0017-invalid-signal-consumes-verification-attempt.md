# Invalid Signal Consumes a Verification Attempt

We decided that a ready Signal which fails strict validation (malformed JSON, missing or mistyped fields, `ticket_id` mismatch, invalid status or scope, unparseable timestamp) is treated as a failed Verification Attempt rather than as an absent signal: the format error is fed back into the active Worker session as diagnostics and consumes one unit of the Circuit Breaker budget. Treating it as absence would hand control to the spec 03 nudge and crash-retry paths, letting an agent that cannot produce a valid completion artifact spin without bound; counting it subjects that failure to the same bounded safety net as failing tests. Unknown extra fields remain tolerated so the Signal schema can evolve without breaking older Workers. (Amended by ADR 0024 and ADR 0025: While an invalid signal still consumes one verification attempt, the schema is governed by the domain rather than skill documentation, raw malformed payloads are archived to `.agent/logs/` before consumption, and a one-shot self-correctable retry exemption under `SIGNAL_FORMAT` is granted before operator escalation when remaining budget exists, avoiding run-ending halts on minor format typos while preserving the bounded safety net.)
