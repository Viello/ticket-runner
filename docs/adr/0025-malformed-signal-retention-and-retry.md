# Malformed Signal Retention and Retry

We decided that malformed ready and question signals are cheap format corrections rather than run-ending protocol failures: the Gatekeeper copies the raw payload atomically to `.agent/logs/<ticket_id>_malformed_{ready|question}.json` before parsing or deletion, and persists diagnostic markdown reports to `.agent/logs/<ticket_id>_diagnostic.md` on every escalation attempt before prompting the operator so evidence is preserved regardless of operator action. The failure label vocabulary splits syntax and schema format errors (`SIGNAL_FORMAT`, marked `self_correctable=True`) from security boundary violations (`PROTOCOL`, e.g. ticket deletion, unauthorized ticket mutation, or missing signal files, marked `self_correctable=False` which escalate immediately). When the configured escalation policy would otherwise halt the run on a format error and remaining attempt budget exists, a shared one-shot per-ticket exemption automatically consumes one attempt, publishes a `SIGNAL_FORMAT_RETRY` status event naming the offending field, and feeds the parser error back into the active worker session as diagnostics. Three residues are explicitly accepted: a format error occurring after an operator-initiated `RETRY` at the Circuit Breaker prompts immediately without re-arming the exemption, the ticket processor's background malformed-question catch remains a best-effort race guard that does not consume a verification attempt, and a Target Project repaired by hand before a catalog republish carries string examples until a future skills sync overwrites it with the updated catalog.
