# Single-Commit Ticket Lifecycle and Ephemeral Queue Clean Slate

We decided that completing a ticket produces exactly one atomic commit containing the code, tests, newly recorded gotchas, and the relocated ticket file (`Status: completed`, `Completed: <timestamp>`) without recording the commit SHA inside the ticket frontmatter, which eliminates the cryptographic paradox that previously required a redundant second commit. Furthermore, we treat specifications (`docs/specs/<spec-slug>.md`), ticket directories (`docs/tickets/<spec-slug>/`), and feature gotchas as ephemeral scaffolding: when a spec's queue finishes and passes all verification, the Runner interactively prompts the user (`[Y/n]`) to clean slate, backing up the completed artifacts to untracked `.agent/archive/<spec-slug>/` and removing them from git tracking in a single `chore(queue)` commit. This establishes working code, unit tests, and CLI interfaces as the authoritative source of truth, eliminates long-term context token burn from dozens of obsolete markdown files, and protects root living documents (`AGENTS.md`, `ARCHITECTURE.md`, `CONTEXT.md`) from clutter by requiring explicit user approval for any additions.
