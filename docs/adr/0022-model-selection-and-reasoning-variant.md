# Model Selection and Per-Ticket Reasoning Variant

The Runner needs to support multiple LLM providers (e.g. DeepSeek, Qwen) selectable at startup, and to let individual tickets tune the model's reasoning depth independently of model identity. We chose to expose a `model:` block in `config.yaml` containing a labelled list of provider/model strings and a `default_reasoning` value. At startup the Runner accepts an optional `--model <id>` CLI flag; when it is absent and multiple models are configured the Runner presents an interactive numbered prompt; when exactly one model is configured it auto-selects silently. The selected model is stored as `selected_model` in `.agent/state.json` so crash recovery can restore it without re-prompting. The Doctor fails pre-flight if `model.models` is empty or missing. Model identity is session-scoped (fixed for the entire Runner run); only the reasoning variant floats per-ticket. Tickets declare an optional `Reasoning:` frontmatter field (title-cased, matching the existing `Status:` and `Security:` convention); the Runner reads it case-insensitively and passes it as `--variant` to every `opencode run` call under that ticket — initial Session Run, handoff resumes, and answer-resume runs. When the ticket omits `Reasoning:`, the Runner falls back to `model.default_reasoning`; when that is also empty, `--variant` is omitted entirely, letting OpenCode apply its own default. Variant strings are passed through without Runner-level validation; OpenCode surfaces errors for invalid values. The alternative — per-phase reasoning (lighter for handoffs, heavier for initial implementation) — was rejected as premature complexity; the alternative — full model switching per ticket — was rejected because it leaks provider routing knowledge into ticket files and complicates the command contract. `--model` CLI flag values are validated against the configured list; arbitrary strings are rejected to keep the list the authoritative menu.
