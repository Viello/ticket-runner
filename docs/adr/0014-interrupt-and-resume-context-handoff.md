# Interrupt-and-Resume Context Handoff

The Spec 03 assumption that the Runner can message a live Worker session and choose session ids is not supported by the OpenCode CLI: `opencode run --session <id>` only resumes an existing session, session ids are generated by OpenCode (`ses_…`) and merely reported in the JSON event stream, piped stdin is consumed once at startup, and a second concurrent run against one session is queued or discarded as racy — while the only real steering channel (`opencode serve` plus `prompt_async`/`abort`) would violate ADR 0001's subprocess-only rule. We therefore implement the Context Handoff as an interrupt-and-resume protocol: at the 135k threshold the Runner terminates the active Session Run, immediately starts a fresh process on the *same* session carrying the handoff instruction that invokes `.agents/skills/handoff/SKILL.md`, accepts the Checkpoint only when it was written fresh (existence plus `mtime >= handoff_requested_at`), then opens a brand-new session whose id is learned from the stream, capping consecutive handoffs (5) before escalating for human intervention. This supersedes the spec's wording about messaging the active session and instantiating `session_b_id` verbatim.
