# Signal Schema Ownership and Contract Checks

We decided that the domain owns the authoritative field inventory and payload schemas for both ready and question Signals (`runner.domain.signal_contract`), replacing four previously hand-maintained, drifting copies across the task prompt, the execution skill, and individual parsers. The prompt dynamically renders complete, valid protocol sections from the domain schema and explicitly declares itself authoritative over any other document. The execution skill (`implement-ticket-runner/SKILL.md`) drops duplicate schema definitions and defers completely to the prompt protocol sections via a pointer sentence. To guarantee that provisioned skill files in arbitrary Target Projects remain compatible before workers spend execution budget on them, pure markdown contract checking (`check_markdown_signal_examples`) runs at three enforcement points: as a Doctor pre-flight check before worker dispatch, as a blocking gate in the skills catalog publish script (`scripts/publish_agent_skills.py`), and as a repository unit test over canonical execution skills. This prevents drift between prompt guidance and parser validation without requiring a heavyweight external JSON Schema dependency.
