# Dual-Track Skill Segregation and Human Control Routing

We decided that interactive Human + AI pair programming skills (`to-tickets`, `implement`, `code-review`, `security-review`, `diagnosing-bugs`, `handoff`) and autonomous Ticket Runner skills (`to-ticket-runner`, `implement-ticket-runner`, `code-review-ticket-runner`, `security-review-ticket-runner`, `diagnosing-bugs-ticket-runner`, `handoff-ticket-runner`) form strictly segregated tracks that never share mutable workflow skills. Interactive skills converse directly with the human operator in the chat turn and must contain zero autonomous Runner instructions, uncommitted-diff overrides, Gatekeeper prohibitions, or `.agent/` Signal paths. Headless `-ticket-runner` skills are marked `disable-model-invocation: true` (preventing auto-selection in chat), evaluate uncommitted working-tree changes (`git diff HEAD` plus untracked files) against ticket acceptance criteria without prompt ambiguity, and route human decision points—un-remediable `CRITICAL` or `HIGH` findings, spec contradictions, missing secrets, or Stuck-Test-Suite isolation failures—exclusively through durable Question Signals (`.agent/questions/<ticket_id>.json`) that halt the Gatekeeper at `WAITING_FOR_USER` and prompt the operator via Discord or the Terminal. This amends ADR 0008 (standardizing on `implement-ticket-runner`), ADR 0013 (routing pre-signal security audits through `security-review-ticket-runner`), ADR 0014 (routing context handoffs to `handoff-ticket-runner` writing directly to `.agent/checkpoints/<ticket_id>/handoff.md`), and ADR 0020 (auditing worker telemetry for `-ticket-runner` skills).
