# Spec Context Excerpt Injection in Worker Prompts

To prevent OpenCode Workers from developing tickets in isolation without broader architectural context, we decided to link each Ticket to its originating Spec file (via an explicit `Spec: docs/specs/<spec-slug>.md` header with automatic fallback to `docs/specs/<directory-slug>.md`). Rather than injecting the entire spec into the prompt or relying solely on unguided tool reads, the Runner automatically extracts and inlines a lightweight Spec Excerpt (`## Problem Statement` and `## Solution`, ~300 tokens) into the Worker's initial prompt alongside a path pointer to the full file. This grounds the Worker in the overarching architectural intent and system boundaries at negligible token cost (~0.2% of the 150k budget) while leaving comprehensive spec details available on disk if deeper exploration is required.
