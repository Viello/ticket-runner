# Clean Architecture and Concentric Layering for Runner File Structure

We decided to organize the Ticket Runner source tree into strict concentric Clean Architecture layers (`runner/domain/`, `runner/application/`, `runner/ports/`, `runner/adapters/`) and a dual-tier test suite (`tests/unit/`, `tests/specs/`, `tests/fakes/`) rather than maintaining a flat orchestrator package with root-level delivery scripts. This guarantees that domain rules and use case interactors maintain zero inward dependencies on external drivers (`discord.py`, `rich`, `pyyaml`, `subprocess`), isolates external boundaries behind injectable protocols per ADR 0006, enforces Single Responsibility with modular files under 200 lines, and allows comprehensive in-memory test execution with deterministic fakes.
