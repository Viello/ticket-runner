# T121 — Unify Antigravity Token Occupancy, Stall Heartbeat, and Ready-Signal Precedence
Status: completed
Completed: 2026-10-27T13:47:30Z
Spec: docs/specs/16-live-run-gatekeeper-and-antigravity-telemetry-remediation.md
Blocked by: None
Reasoning: medium

### Requirements
- Compute true per-step context-window occupancy on Antigravity `step_update` events (`input + output + reasoning + cache_read + cache_write` per ADR 0015) and prevent Antigravity's cumulative end-of-turn `result.usage` sum from being fed into `BudgetMonitor.observe()` whenever per-step `step_update` usage has already been observed during the turn (using `result.usage` for `BudgetMonitor` only when no `step_update` usage was emitted, while preserving `result.usage` inspection inside `_detect_empty_success_result`).
- Decouple `last_step_time` and `step_counter` updates in `WorkerSupervisor.run` from `event.token_usage` presence and OpenCode's `"step_finish"` event name: advance `last_step_time` and `step_counter` on every completed step (`event.type == "step_finish"` or `event.type == "step_update"` with `part.get("state") in ("DONE", "ERROR")`) and advance `last_step_time` on active tool invocations (`step_type == "tool"`), even when `event.token_usage is None`.
- Persist observed per-step token occupancy to `.agent/state.json` via `StateCoordinator.record_tokens()`, publish `StatusEvent(last_event="STEP_FINISHED", token_count=latest_occupancy)` to `StatusPublisher` (`.agent/status.json`), and forward active Antigravity tool invocations (`event.type == "step_update"` with `step_type == "tool"` and `state == "ACTIVE"`) to `_ui_event_sink` alongside `"tool_call"` and `"tool_use"`.
- Give a valid `.agent/signals/<ticket_id>_ready.json` on disk precedence over late `KILLED_HANDOFF` (135k) and `KILLED_CEILING` (150k) budget actions in both `WorkerSupervisor` and `HandoffCoordinator.run_cycle` so a finished Ticket is never discarded to run a redundant Context Handoff or ceiling escalation.
- Jump-start orientation: inspect `runner/adapters/antigravity/antigravity_worker.py` (`_extract_token_usage`, `_detect_empty_success_result`, `decode_event`), `runner/application/worker_supervisor.py` (`_format_tool_event`, `WorkerSupervisor.run`), `runner/application/handoff_coordinator.py` (`HandoffCoordinator.run_cycle`), `tests/unit/adapters/test_antigravity_worker_adapter.py`, `tests/unit/application/test_worker_supervisor.py`, and `tests/unit/application/test_handoff_coordinator.py`. Verify with `python -m pytest tests/unit/adapters/test_antigravity_worker_adapter.py tests/unit/application/test_worker_supervisor.py tests/unit/application/test_handoff_coordinator.py -x`.

### Acceptance Criteria
- Streaming Antigravity `step_update` events carrying `input_tokens`, `cache_read_tokens`, `output_tokens`, and `thinking_tokens` record true context-window occupancy (`input + cache_read + output + reasoning`) in `BudgetMonitor`, `StateCoordinator` (`.agent/state.json`), and `StatusPublisher` (`.agent/status.json`), and a closing `result` event with a multi-step cumulative `usage` sum does not overwrite occupancy or falsely trip the 150k ceiling when `step_update` usage was already observed.
- Long chains of Antigravity tool `step_update` events (`step_type == "tool"`, `token_usage is None`) advance `last_step_time` (and `step_counter` on `DONE`/`ERROR`) and emit formatted tool lines to `_ui_event_sink`.
- Genuine mid-turn Antigravity `step_update` occupancy crossing 120k, 135k, or 150k with no ready Signal on disk triggers `BudgetAction.WARN`, `RunTerminationReason.KILLED_HANDOFF`, and `RunTerminationReason.KILLED_CEILING` respectively.
- When `.agent/signals/<ticket_id>_ready.json` is already present on disk when 135k or 150k is crossed on the closing step or `result`, `WorkerSupervisor` suppresses `KILLED_HANDOFF` / `KILLED_CEILING` and `HandoffCoordinator.run_cycle` returns `SingleCycleStatus.READY` instead of launching a Context Handoff or ceiling escalation.

### Gotchas
- In `agy`, `step_update.usage.total_tokens` equals `input_tokens + output_tokens` (omitting `cache_read_tokens` and `thinking_tokens`). Because `TokenUsage.occupancy` returns `self.total` whenever `self.total is not None`, populating `TokenUsage.total` directly from `step_update.usage.total_tokens` under-reports cached context occupancy by ~35k tokens.
- Keep `_detect_empty_success_result` reading `result.usage` directly from the `result` payload so zero-usage truncated turn anomaly detection (Blocker F safeguard) remains unaffected when `result` token telemetry is suppressed from `BudgetMonitor`.
- In `_format_tool_event`, Antigravity tool parameters live under `part["tool_info"]["parameters"]` and the tool name lives under `part["tool_info"]["name"]` or `part["title"]`; ensure `_format_tool_event` extracts both OpenCode and Antigravity tool structures cleanly.
